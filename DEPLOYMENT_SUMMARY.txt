PAYMENT FLOW COMPARISON
================================================================================

BEFORE (Incorrect - PCI Liability):
  1. User fills card form in BantuBuzz (card number, expiry, CVV)
  2. Frontend sends card details to backend
  3. Backend sends card details to SmilePay
  4. BantuBuzz database stores card transaction
  ⚠️ PROBLEM: Card details in our system = PCI compliance liability

AFTER (Correct - PCI Compliant):
  1. User selects card type (Visa/Mastercard)
  2. Frontend sends card_type to /api/smilepay/card
  3. Backend initiates payment with SmilePay (no card details)
  4. SmilePay returns redirect_url to hosted checkout page
  5. Frontend redirects user to SmilePay's secure page
  6. User enters card details on SmilePay (not our system)
  7. SmilePay returns payment status
  8. Webhook callback updates transaction status
  ✅ BENEFIT: No card details in our system = PCI compliant, secure, consistent

API CHANGES
================================================================================

OLD REQUEST (Removed):
  POST /api/smilepay/card
  {
    "card_number": "4111111111111111",
    "expiry_month": "12",
    "expiry_year": "25",
    "cvv": "123",
    "cardholder_name": "John Doe",
    "amount": 10.00
  }

NEW REQUEST (Implemented):
  POST /api/smilepay/card
  {
    "payment_type": "subscription|booking|campaign|cart|collaboration",
    "card_type": "visa" | "mastercard",
    "amount": 100.00,
    "currency": "USD",
    "item_name": "Premium Subscription",
    "item_description": "Monthly premium plan",
    "return_url": "https://...",
    "result_url": "https://...",
    "cancel_url": "https://...",
    "failure_url": "https://..."
  }

OLD RESPONSE:
  {
    "success": true,
    "payment_id": 123
  }

NEW RESPONSE:
  {
    "success": true,
    "order_reference": "ORD_SUBSCRIPTION_123_...",
    "redirect_url": "https://checkout.smilepay.co.zw/...",
    "message": "Redirecting to visa payment page",
    "status": "PENDING"
  }
